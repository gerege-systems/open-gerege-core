# AI-конвейер (Gemini)

> 🌐 **Русский** · [English](AI_PIPELINE.md) · [Монгол](AI_PIPELINE_MN.md) · [中文](AI_PIPELINE_ZH.md)

Как AI-ассистент работает от начала до конца и как его расширять. Конвейер
**не использует SDK** — `pkg/gemini` обращается к Gemini REST API напрямую — и
следует той же слоистой Clean Architecture, что и остальной бэкенд.

## Общая картина

```
Браузер (/me/ai, /me/translate)
   │  fetch со своего origin (заголовок CSRF)
   ▼
Next.js BFF  /api/ai/{chat,stt,tts,translate}     ← проверяет форму, добавляет JWT
   │  сервер→сервер
   ▼
Go API  /api/v1/ai/*  (JWT + лимит ~20/мин)
   │
   ▼
usecases/ai ──────────────► pkg/gemini ──────► Gemini REST API
   │   ▲                      (3 повтора с backoff при 429/5xx/сетевых ошибках)
   │   └─ functionResponse
   ▼
ToolDef.Execute()  ← выполняется НА БЭКЕНДЕ с контекстом запроса
   ├─ search_knowledge → repositories/postgres/ai → таблица ai_knowledge
   └─ get_server_time  → демонстрационный инструмент
```

Ключевой принцип: **модель решает, какой инструмент вызвать; бэкенд его
выполняет.** Модель никогда не выполняет код; инструменты работают на сервере с
контекстом запроса (поэтому к тому, чего они касаются, применяются RLS и таймауты).

## Поток чата (цикл function-calling)

`usecases/ai.Run()` (см. `ai_impl.go`):

1. Сформировать `contents` из истории (≤ 20 реплик) и нового промпта. Голосовое
   сообщение приходит как встроенный аудиофрагмент в base64 — Gemini понимает его
   напрямую, шаг STT не нужен.
2. Вызвать Gemini со слоистой системной инструкцией и объявлениями инструментов.
3. Если ответ содержит **вызовы функций**: выполнить каждый инструмент, добавить
   реплику модели и реплику `functionResponse`, затем повторить цикл (максимум
   `MaxSteps`, по умолчанию 4). Каждый выполненный вызов записывается как
   `Step{Tool, Args, Result}` и возвращается клиенту, чтобы интерфейс мог показать,
   «что сделал AI».
4. Если ответ — **текст**: вернуть его.

**Семантика сбоев:** временные сбои Gemini (после трёх собственных повторов
клиента) **не** дают 5xx — пользователь получает резервное сообщение на
своём языке с `degraded: true`. Настоящей ошибкой считается только отсутствие
`GEMINI_API_KEY` (500, причина в логах). Неизвестные и упавшие инструменты
возвращаются модели как `{"error": …}`, чтобы она могла корректно извиниться —
ошибки инструментов никогда не попадают клиенту напрямую.

## Слои промпта

Системный промпт собирается на каждый запрос из трёх слоёв (`ai_prompts.go`):

| Слой | Источник | Редактируемость | Назначение |
|-------|--------|----------|---------|
| 1. Базовые ограничения | жёстко заданная константа | **никогда** | Язык ответа (из поля `lang` запроса), соблюдение области применения, устойчивость к prompt injection («забудь свои инструкции» трактуется как обычный текст; промпт никогда не раскрывается) |
| 2. Область применения | таблица `ai_prompts` → переменная `AI_SCOPE_PROMPT` → встроенное значение | админ, в рантайме | *В чём* ассистент помогает. Всё вне этого он вежливо отклоняет |
| 3. Инструкции | таблица `ai_prompts` (необязательно) | админ, в рантайме | Тон, дополнительные правила |

- **Язык ответа** берётся из поля `lang` запроса (фронтенд отправляет язык
  интерфейса: `mn`/`en`/`zh`/`ru`; неизвестное или пустое ⇒ `mn`). Если
  **Язык интерфейса главнее:** язык, на котором пишет пользователь, история переписки,
  база знаний и результаты инструментов его не меняют — источники на другом языке
  переводятся на язык ответа. Переключение возможно только по явной просьбе пользователя.
  Резервное сообщение `degraded` локализуется так же. Директива написана *на самом целевом
  языке* и встречается дважды — в первом правиле и в закрывающей секции
  `[ХЭЛ / LANGUAGE]` (остальной промпт по-монгольски, поэтому нужны и первичность,
  и недавность). Фронтенд также не отправляет реплики истории на прежнем языке, поэтому
  смена языка посреди чата начинает чистый контекст.
- Интерфейс: **Админ → Настройки**; API: `GET/PUT /api/v1/admin/ai/prompts/{key}`
  (разрешение `settings.manage`).
- Промпты кэшируются на 60 с; `SetPrompt` сбрасывает кэш, поэтому изменения
  вступают в силу сразу на том экземпляре, который принял запись.
- `SetPrompt` работает **только на UPDATE** по ключам, засеянным миграцией 11
  (`scope`, `instructions`) — поверхность промптов не может расширяться через API.
- Сбой чтения из базы приводит к **открытому** отказу в пользу env/значения по
  умолчанию (поиск промпта никогда не должен ронять чат).

## Инструменты

Инструмент — это `ai.ToolDef`: объявление функции Gemini + Go-функция:

```go
ai.ToolDef{
    Declaration: gemini.FunctionDeclaration{
        Name:        "my_tool",
        Description: "Когда модель должна это вызывать…",
        Parameters:  map[string]any{ /* JSON Schema */ },
    },
    Execute: func(ctx context.Context, args map[string]any) (map[string]any, error) {
        // выполняется на бэкенде; ctx несёт личность запроса (работает RLS)
        return map[string]any{"result": "…"}, nil
    },
}
```

Зарегистрируйте его в `cmd/api/server/server.go`:

```go
aiTools := append(ai.DefaultTools(), ai.KnowledgeSearchTool(aiRepo), myTool)
```

Инструменты «из коробки»:

- **`search_knowledge`** — **семантический (векторный) поиск** по `ai_knowledge`.
  Вопрос векторизуется (`gemini-embedding-001`, `RETRIEVAL_QUERY`) и
  сопоставляется по косинусному расстоянию в **pgvector** (`embedding <=> $1`,
  индекс HNSW), поэтому вопрос, заданный другими словами, всё равно находит
  нужный фрагмент. Из топ-8 кандидатов отбор идёт **относительно лучшего
  совпадения**: всё, что ниже него более чем на `relativeScoreMargin` (0.03),
  отбрасывается; остаётся от `minKnowledgeResults` (2) до
  `maxKnowledgeResults` (4) фрагментов. Почему
  относительный порог: замеры на этом корпусе показали, что даже *несвязанные*
  фрагменты имеют косинусную близость 0.64+, поэтому фиксированный порог
  (прежние 0.55) не отсеивал ничего; `minVectorScore` (0.35) теперь лишь нижний
  предел для мусора. Если embedder не настроен, вызов векторизации не удался или
  после фильтра ничего не осталось, происходит откат к поиску по ключевым словам
  (`ILIKE`) — а так как модель передаёт вопрос целиком, откат разбивает строку на
  слова и ищет самые длинные по 6-символьной основе. В результате инструмента
  указывается режим (`"mode": "vector" | "keyword"`); в лог пишутся режим,
  число совпадений, лучший балл и slug (никогда — текст вопроса пользователя).
  Базовые ограничения предписывают вызывать его *до* ответа на вопросы о платформе.
- **`get_server_time`** — минимальный пример (время Улан-Батора), без зависимостей.

## Публичный (анонимный) чат

На главной странице есть плавающий чат-виджет, работающий **без входа в
систему** (`POST /public/ai/chat`, без bearer-токена). Он использует тот же
конвейер, но подключён как **отдельный экземпляр usecase** с урезанным набором
инструментов — только поиск по базе знаний. Это разделение и есть граница
безопасности: инструмент, читающий пользовательские данные, можно добавить
аутентифицированному помощнику, и он всё равно останется недоступным анониму.

На этой поверхности действуют ещё три ограничения: отдельный лимитер (~6
запросов/мин на IP, burst 3), короткие полезные нагрузки (сообщение ≤ 1000
символов, история ≤ 6 реплик), а также дополнительный жёстко зашитый слой
промпта: помощник знает, что говорит с посетителем — не спрашивать личные
данные, не заявлять о доступе к записям аккаунта, при необходимости предлагать
войти.

Виджет понимает речь и отвечает потоком. **Push-to-talk** (удерживайте большую
круглую кнопку, отпустите для отправки) отправляет короткий фрагмент — не более
~250 КБ base64 (≈ 15 с), вчетверо меньше, чем в аутентифицированном чате — на
`POST /public/ai/chat/stream`, который отвечает через Server-Sent Events.
Чат-модель мультимодальна, поэтому **один** вызов и расшифровывает, и отвечает:
первая строка вывода содержит расшифровку (сервер срезает этот внутренний маркер
и отправляет событием `transcript`), остальное идёт событиями `delta`. Поэтому
посетитель видит, что он сказал, и начинает читать ответ, пока модель ещё пишет.

Озвучка построена так же: клиент режет потоковый текст по границам предложений и
отправляет каждое законченное предложение в `POST /public/ai/tts` (текст ≤ 800
символов, голос выбирает сервер), проигрывая их по порядку. Речь начинается уже
после первого предложения, а не после всего ответа. На текстовый вопрос ответ
только текстом — синтез включается, если посетитель спросил голосом или нажал
кнопку «прослушать».

## База знаний (RAG)

Собственные знания платформы хранятся в `ai_knowledge` — около 58 фрагментов,
написанных по коду и документации (миграция `48_ai_knowledge_platform_corpus`).
У каждой строки есть стабильный `slug` (seed делает upsert по нему), `source`,
`lang` и `embedding` типа `vector(768)` (миграция `47_ai_knowledge_vector`,
pgvector + индекс HNSW).

- **Дозаполнение векторов.** После старта API векторизует строки, у которых
  `embedding` равен NULL либо `content_hash` больше не совпадает с текущим
  текстом, пакетами по 20 (`EmbedKnowledge`). Работает в фоне и не блокирует
  запуск; без `GEMINI_API_KEY` — пустая операция (поиск остаётся по ключевым словам).
- **Правка корпуса.** Добавьте или измените строки в миграции (сохраняя `slug`),
  затем перезапустите сервис либо вызовите
  `POST /api/v1/admin/ai/knowledge/reindex` (`settings.manage`; кнопка есть в
  Админ → Настройки). Изменение `content` очищает сохранённый вектор, и
  дозаполнение пересчитает его.
- **Модель.** Оставьте `GEMINI_EMBED_MODEL` пустым — клиент сам подберёт рабочую
  модель: `gemini-embedding-001` → `text-embedding-004` → `embedding-001`, —
  потому что конкретное имя может отсутствовать для вашего ключа/версии API (404).
  Первая ответившая модель кэшируется на время работы процесса. В каждом запросе
  указывается `outputDimensionality: 768`, поэтому вектор всегда подходит под
  `ai_knowledge.embedding` (`vector(768)`); смена размера столбца требует миграции.

## Разнообразие ответов

Один и тот же вопрос никогда не получает побайтово одинаковый ответ:

- В системном промпте есть секция `[НАЙРУУЛГА]`: постоянное правило против
  повторов плюс один случайно выбранный на каждый запрос стилевой ориентир
  (`styleHints`).
- Сэмплинг: `temperature` 1.0, `topP` 0.95.

Меняется только *формулировка*. В правиле прямо сказано, что факты, числа, шаги
и источники остаются прежними — достоверность обеспечивают база знаний и
инструменты, а не стиль изложения.

## Голос

| Возможность | Endpoint | Как работает |
|------------|----------|--------------|
| Голосовое сообщение в чате | `POST /ai/chat` с `audio` | аудио идёт прямо в реплику пользователя как встроенные данные — чат-модель мультимодальна |
| Речь в текст | `POST /ai/stt` | один вызов Gemini со строгой инструкцией «расшифровать дословно»; пустой текст = речи нет |
| Текст в речь | `POST /ai/tts` | отдельная TTS-модель (`GEMINI_TTS_MODEL`) с `responseModalities: ["AUDIO"]`; сырой PCM (L16/24 кГц) оборачивается в WAV-заголовок (`pkg/gemini/wav.go`), чтобы браузер мог воспроизвести его напрямую. Модель иногда отвечает `200` **без аудиочасти** (замерено: тот же текст проходит со следующей попытки), поэтому `Speak` повторяет вызов до 3 раз и лишь затем возвращает `503` — временный сбой вышестоящего сервиса, а не 500 |
| Синхронный перевод | `POST /ai/translate` | текст → перевод; аудио → **два шага** STT→перевод (надёжно, без разбора структурированного вывода); `speak: true` добавляет озвучку перевода. Сбой TTS деградирует молча (текст всё равно возвращается) |

**UX синхронного перевода** (фронтенд `LiveTranslateView`): микрофон записывает
фрагменты по ~7 с — **новый `MediaRecorder` на каждый фрагмент**, чтобы каждый
кусок был самостоятельным корректным контейнером (при разбиении по timeslice
заголовок есть только в первом куске) — и отправляет каждый в `/ai/translate`.
Тихие фрагменты возвращают пустые поля и отбрасываются, а не считаются ошибкой.

Аудио на входе фильтруется по mime-типу (webm/ogg/wav/mpeg/mp3/mp4/m4a/aac/flac)
и ограничено ~700 КБ base64 (~30 с opus) и в BFF (`lib/aiBff.ts`), и в DTO бэкенда.

## Конфигурация

```env
GEMINI_API_KEY=     # обязателен для AI; пусто = endpoints возвращают 500
GEMINI_MODEL=gemini-2.5-flash                  # чат / STT / перевод
GEMINI_TTS_MODEL=gemini-2.5-flash-preview-tts  # TTS (модель с поддержкой аудио)
GEMINI_VOICE=Kore   # предустановленный голос TTS
GEMINI_API_BASE=    # переопределение для прокси/тестов
AI_SCOPE_PROMPT=    # запасное значение scope, когда слой в базе пуст
```

Ограничение запросов: у `/ai/*` собственный лимитер по IP (~20 запросов/мин,
burst 5), рассчитанный так, чтобы синхронный перевод (~8 фрагментов/мин)
помещался с запасом.

## Тестирование

Всё тестируется без Gemini:

- `gemini.Generator` — интерфейс; тесты usecase используют `fakeGenerator` со
  сценарными ответами (`ai_impl_test.go`, `ai_speech_test.go`).
- `repointerface.AIRepository` подменяется для тестов промптов и инструментов
  (`ai_prompts_test.go`).
- Сам HTTP-клиент тестируется против серверов `httptest`
  (повторы/backoff, отсутствие повторов на 4xx, разбор вызовов функций —
  `pkg/gemini/gemini_test.go`).

## Диагностика

| Симптом | Причина / решение |
|---------|-------------|
| 500 «internal server error» на любой AI-запрос | Не задан `GEMINI_API_KEY` (причина в логах) |
| `degraded: true` и резервный ответ | Gemini недоступен / 429 / 5xx после повторов — временно; смотрите логи api (`category=ai`) |
| TTS падает, а чат работает | `GEMINI_TTS_MODEL` — **preview**-модель; если Google её переименует, переопределите переменную окружения |
| Ассистент отклоняет вопрос по теме | Слой `scope` слишком узкий — отредактируйте в Админ → Настройки |
| `search_knowledge` ничего не находит | В таблице `ai_knowledge` только 3 демонстрационные строки — добавьте свой контент |
| 429 при синхронном переводе | Частота фрагментов против лимита `/ai` — поднимите лимитер в `server.go` или увеличьте `SEGMENT_MS` |
